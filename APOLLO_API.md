# Apollo API connection

The local Vite server exposes server-side proxies for Apollo People API Search, Organization Search, People Enrichment, and AI Assistant tasks. The browser never receives the API key.

1. Create an Apollo API key with access to People API Search, Organization Search, Bulk Organization Enrichment, People Enrichment, and `api/v1/agents/task` plus `api/v1/agents/poll_task` if you want connected Luna chat. Entitlements depend on your Apollo account.
2. In Admin Settings → Integrations, paste the key and choose **Connect Apollo**. The local server validates it with Apollo's zero-credit `GET /api/v1/auth/health` endpoint.
3. The key stays in local server memory and is not written to browser storage or disk. It is cleared when the preview server stops. You can still configure `APOLLO_API_KEY` in `.env.local` for a persistent local-server configuration, then restart the preview.
4. The Find People search form will query Apollo; without a key, the interface stays in clearly labeled demo mode.

Apollo API keys can act as a workspace-level API user, and access depends on the key's selected endpoints and your Apollo plan. Review [Apollo API authentication](https://docs.apollo.io/reference/authentication) and [Create an API key](https://docs.apollo.io/docs/create-api-key) before connecting. Connected Assistant tasks still require the separate **Run in Apollo** approval.

The proxy calls `POST https://api.apollo.io/api/v1/mixed_people/api_search`, passes the key in the `x-api-key` header, and accepts up to 100 results per page and 500 pages. The UI offers 25, 50, and 100 results per page. It supports current-title inclusion, current and past-title exclusions, person or employer-HQ location, include/exclude employer domains, industry, broad company keywords, seniority, email-status, employee-count ranges, revenue bounds, technologies, active hiring titles/locations/count/date ranges, name, and pagination filters. Employee ranges accept forms such as `1-50; 1,000-5,000` or Apollo's comma-pair format `1,50; 1000,5000`. Apollo's documented People API Search endpoint uses no credits, but eligibility and access can depend on the Apollo account.

An explicit per-person email lookup uses Apollo's People Enrichment endpoint after a direct user action in People. The proxy sends the Apollo person ID and explicitly leaves personal-email, phone, and waterfall enrichment disabled. Apollo documents enrichment as potentially credit-consuming (1–9 credits per person depending on results and configuration). Connected Luna chat uses Apollo's Assistant task endpoint; its task credit use varies by action and is not estimated by this prototype.

Known API boundaries are surfaced in the results UI: People API Search does not return email addresses or phone numbers; exact company-name matching, past-company matching, a general known-domain-only switch, radius search, department selection, excluded company keywords, and several known/unknown states are not exposed by that endpoint. Keyword type selection maps to Apollo's broad `q_keywords` search rather than a field-specific match. Domain filters accept include and exclude lists, but Apollo applies include matches across current or previous employers rather than limiting them to the selected company-history mode. Email enrichment is individual and user-triggered; the prototype does not request personal emails or phone numbers or create records in the Apollo workspace.

The Vite proxy is for the local preview. A production deployment needs a server-side API proxy configured with its own secret manager; the static Sites worker remains unchanged and does not receive the key.

## Organization Search

The Companies workspace can search Apollo's `POST /api/v1/mixed_companies/search` endpoint through `/api/apollo/companies/search`. The proxy maps company name, keyword include/exclude, industry, headquarters include/exclude, employee ranges, domains include/exclude, technology, active job titles and locations, active job counts, job posting dates, revenue bounds, most recent and total funding bounds/dates, headcount growth, and lookalike organization IDs. The form exposes company name, keywords, industry, HQ, employee range, and advanced domain, keyword-exclusion, revenue, hiring, funding, and headcount-growth filters. Select up to five Apollo results to search for similar companies; Apollo requires saved organization IDs for this filter. Results are Apollo organizations that are not yet saved as accounts. Apollo documents this endpoint as costing 1 credit per page (up to 100 records); the UI discloses that cost before each explicit search or page change. It does not create Apollo account records. **Save locally** adds a result to this prototype's browser workspace only. See [Apollo Organization Search](https://docs.apollo.io/reference/organization-search) for current filters, access requirements, and billing.

## Bulk Organization Enrichment

The Companies workspace can enrich up to ten selected Apollo organizations in one request through `POST /api/v1/organizations/bulk_enrich`. The proxy sends only company name, domain, website, and LinkedIn URL identifiers, and validates the ten-company limit. Before sending the request, the UI shows the selected companies and requires a separate approval click. Apollo documents 1 credit per organization. Returned data may include revenue, employee count, funding, phone, location, technologies, headcount growth, and corporate hierarchy. The result refreshes matching browser-local company records; it does not create or update Apollo accounts. See [Bulk Organization Enrichment](https://docs.apollo.io/reference/bulk-organization-enrichment) for current access and response fields.

## Apollo AI Assistant

When `APOLLO_API_KEY` is configured, Luna chat can submit a user-approved request through Apollo's documented `POST /api/v1/agents/task` endpoint and poll progress through `POST /api/v1/agents/poll_task`. The task ID is stored with that browser-local chat so follow-up messages can continue the same Apollo Assistant conversation. The browser never receives the API key. Apollo may execute account actions as the API key's acting user; the prototype requires an explicit **Run in Apollo** click for each submitted instruction.

Apollo documents variable credit use for assistant tasks and does not expose a per-task cost estimate or credit cap in this API. Therefore, the prototype cannot enforce its local chat credit cap for connected Apollo Assistant tasks. The connected UI warns about variable credits and sends the prompt plus selected product context, chat instructions, and saved personal preferences to Apollo only after approval. Use Apollo's own account controls to manage the actual allowance. API task access must be enabled for the key; a configured key alone does not guarantee entitlement.

The assistant composer supports browser speech dictation when the browser exposes the Web Speech API. Recognized text is placed in the prompt for review; it is not submitted automatically. Browser support and microphone permission are required. This follows Apollo's [AI prospecting guidance](https://knowledge.apollo.io/hc/en-us/articles/43512338043789-Find-Prospects-with-the-AI-Assistant), which documents microphone voice-to-text for assistant prompts.

## Other workspace sections

The broader Apollo-style navigation is implemented as a local demo workspace in `src/WorkspaceModules.jsx`. Companies, lists, enrichment status, sequences, email drafts, calls, tasks, meetings, conversation summaries, deals, workflows, analytics, and admin settings use sample data persisted in the browser; they do not sync with Apollo account records or external services. Luna chat uses Apollo's Assistant task API when a key with the required access is configured and the user approves each request. Without that key, chat falls back to a local sample-data helper that can rank contacts and companies, create contact and company records, save people or companies to named lists, create reviewed deals for known companies, log reviewed call outcomes and notes, save record-level research notes based on local data, update contact and company fields and deal stage, amount, close date, or owner after review, pause or activate sequences after review, update the selected AI context from chat, create and optimize sequence drafts, create a reviewed meeting no-show follow-up workflow, enroll a person in a local sequence plan, draft outreach, export People and company lists as reviewed CSV files from local browser records, and summarize workspace records. Sequence creation reviews include editable channels, delays, email copy, call scripts, and LinkedIn messages; the draft is stored only after review, and creating it does not enroll contacts or send outreach. These local notes do not include Apollo web research or buying-intent signals. Assistant-generated local writes, exports, and contact enrichment require review or explicit credit approval; connected Apollo tasks require approval before submission. In the Agents tab, connected **Run now** and **Configure schedule with Apollo Assistant** requests are queued for explicit approval. Schedule controls compose the proposed frequency, time, and credit limit; the request asks Apollo Assistant to show those settings and ask before activation. This preview cannot verify the saved Apollo schedule. The local demo schedules remain browser-local and run only while this page is open. See Apollo’s [AI Assistant agents guide](https://knowledge.apollo.io/hc/en-us/articles/48316596060941-Use-Agents-to-Improve-Outbound-Work) for supported agents and account requirements.
